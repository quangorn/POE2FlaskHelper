# POE2FlaskHelper

A tray application for Windows x64: it reads HP/Mana/Energy Shield/Ward/Rage from the
memory of `PathOfExile.exe` (Path of Exile 2) and, when a value drops below the
threshold, sends the flask key to the game. It never writes to game memory.

The Russian version of this document is [`README.ru.md`](README.ru.md).

## Build and tests

`./build.sh` (cygwin bash): vcvars64 → VS cmake/ninja → Release → version gates
(SPEC §2.4: `./version.sh check`, stdout `--version`, PE resources) → strip + integrity
→ `ctest` (red tests stop the build before packaging) → dist zip
`dist/POE2FlaskHelper-<version>-poe2-<gamever>-win64.zip` (exe + `offsets.json` +
`README.txt` + `README.ru.txt`; `config.json` is NOT in the archive — the app
generates it on first run) and a smoke launch of the staged copy, then
`./release.sh` publishes the zip as a GitHub release (tag
`v<version>-poe2-<gamever>`, English title and notes). `./build.sh --no-upload` builds
and packages without touching GitHub. `<gamever>` is the game patch version from the
`GameVersion` key of `offsets.json` (written by `find_offsets.py --save`).

The build requires Visual Studio 2022 with the "CMake tools for Windows" component
(cmake + ninja from the VS installation), python in PATH (the zip composition gate),
and `gh` for the upload (`gh` in PATH, fallback
`C:\Program Files\GitHub CLI\gh.exe`; `--no-upload` skips it). Do not run the build
while `POE2FlaskHelper` is running: the smoke step finds the tray window by class and
posts `WM_CLOSE` to it.

## Versioning

The format is `1.major.minor` (the leading digit is the series): **major** for new
features (`1.1.0 → 1.2.0`), **minor** for fixes and small behavior changes
(`1.1.0 → 1.1.1`), a series change (`2.0.0`) only for a substantial architecture
rework. If the project code (`src/` and the `res/` assets/rc/manifest) has not
changed, the exe is current and the version is not bumped — a new game patch with new
offsets ships as a new archive named by the new poe2 version, without an exe version
change. History — [`CHANGELOG.ru.md`](CHANGELOG.ru.md) (Russian) and
[`CHANGELOG.md`](CHANGELOG.md) (English release notes).

The number lives in one place — `project(POE2FlaskHelper VERSION ...)` in
`CMakeLists.txt`; it reaches `--version`, VERSIONINFO, the manifest, the generated
READMEs and the zip name. Bumps go only through `./version.sh`:

```
./version.sh major "описание фичи" --en "English release note"   # 1.1.0 -> 1.2.0
./version.sh minor "описание фикса" --en "English release note"  # 1.1.0 -> 1.1.1
./version.sh series "описание" --en "English note"               # series change
./version.sh check                      # the code <-> version gate (build.sh)
```

`version.sh` edits `CMakeLists.txt`, `CHANGELOG.md` (English) and `CHANGELOG.ru.md`
(Russian), and never
commits; after a bump run `./build.sh` and commit `CMakeLists.txt` + `CHANGELOG.md` +
`CHANGELOG.ru.md`. Rule 3 is checked at the bump (refusal when the code did not
change; the exception is `--force`) and in the build (red = no zip). Details — SPEC §2.4.

## Requirements

For the app: Windows x64 and the Visual C++ v14 x64 Redistributable
(https://aka.ms/vs/17/release/vc_redist.x64.exe). For the `scanner/` tools:
Windows-native Python 3.x 64-bit, `pymem` is not required. Launch details and options
are in [`scanner/README.md`](scanner/README.md).
